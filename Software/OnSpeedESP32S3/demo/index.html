This mode runs the same C++ core in your browser, compiled to WebAssembly: virtual sensor bytes, median and average filters, AOA curve, tone choice, tone synth, G5 parser and the "#1" display sentence. The flight model is a simple one so you can explore the bands; it is not RV-4 data.

Checks on the virtual board's output

What the simulator cannot show

  • Real sensor behaviour: the pressure sensors, IMU and flap pot are simulated. The board parses the same bytes a Honeywell sensor sends, but I2C timing, noise and drift on real parts are untested.
  • Real audio hardware: the tone samples are real board output, but no I2S DAC or audio panel is attached. Levels into an intercom need a bench test.
  • Timing and CPU load: QEMU does not model ESP32-S3 speed, so whether everything fits in real time with Wi-Fi running is unproven.
  • AHRS: attitude comes from the simulated G5. The Gen2 Madgwick/Kalman code is not in this test.
  • Wi-Fi web UI, SD logging and the real M5Stack screen are not in this test. The display here redraws from the board's serial sentences with the M5 drawing rules.
  • Aerodynamics: the flight is scripted, and manual mode uses a simple flight model. The test proves the port matches Gen2 logic, not that Gen2's calibration fits your aircraft.
